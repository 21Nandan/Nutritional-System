# Data: provenance, pipeline and dictionary

## Current product data (since 2026-10-29)

The catalogue, search, barcode lookups, comparisons and healthier alternatives all use
[Open Food Facts](https://world.openfoodfacts.org) (ODbL 1.0; photos CC BY-SA), a community database:

- Catalogue pages and search use the search service at `search.openfoodfacts.org`. By default only
  products sold in India (`countries_tags:"en:india"`) with a stated energy value are listed, most
  scanned first; text searches are ranked by relevance.
- The service matches whole words, so an unfinished last word ("cadbury da") is matched against the
  word starts of the first 100 results for the earlier words. A 8–14 digit query is looked up as a
  barcode. Ingredient text is not searchable through this service.
- Single products come from the product API (`/api/v3/product/<barcode>`), cached for 7 days.
- Each product's EATGOOD category is taken from its most specific Open Food Facts category.

Values are community-contributed and can be wrong or missing; missing values are shown as "Not
stated" and never treated as zero.

## The former built-in catalogue (quarantined)

The 852-product catalogue described below is **no longer used by the app**. Its files are kept,
unchanged, in `data/quarantine/` (with the generator script) and are not deployed. Links or saved
selections that still use its IDs (`IND_PKG_###`) get a "no longer available" message.

### Provenance (verified)

**The catalogue is synthetic.** Running `data/quarantine/generate_initial_data.py` (seed 42) reproduces every
catalogue file byte for byte. Product names and brands are real; nutrient values (`random.uniform`
ranges per category), ingredient lists (one of 29 templates), allergen declarations
(`random.choice`) and barcodes (`"890"` + 10 random digits) are generated. The original files said
`data_source = "Label Scan / Retail Packaging Audit 2026"` and `"Verified"`; that was false and has been
relabelled. Every record carries a "Synthetic" status badge in the app, and the footer and "About the data" page say so.

Licence: generated by this project (MIT). No third-party data is in the catalogue.

on the `backup-antigravity-original` branch.

### Images

26 products have a photo, listed in `data/product_images.csv` and loaded from Open Food Facts'
public image server (`images.openfoodfacts.org`, CC BY-SA). How they were checked (2026-10-29):

- The original 38 links pointed at `images.openfoodfacts.net`, Open Food Facts' password-protected
  **staging** server, so browsers could not load any of them and the app showed placeholders.
- `scripts/refresh_product_images.py` (removed with the quarantine) looked up each image barcode on the production API (run on
  GitHub Actions, workflow "Refresh product images"). It recorded the current production image URL and
  the product name Open Food Facts holds (`off_product_name`).
- Each Open Food Facts name was compared with the catalogue name. 26 match the same product
  (`review_status = name_checked`).
- 12 were removed because Open Food Facts holds a different product or doesn't say which variant it is.
  These products show the category placeholder instead.
  - Different product: Bingo Masala Madness (OFF: Tomato Madness), Balaji Wafers Masala (Sev Murmura),
    Britannia Time Pass (Vita Marie Gold), Oreo biscuits (Cadbury Dairy Milk Oreo bar), Epigamia
    strawberry smoothie (natural yogurt), Pringles South African Peri Peri (Kickin' Peri Peri),
    Parle-G Gold (regular Parle-G).
  - Variant not stated: Too Yumm Tangy Tomato, Too Yumm Karare Munchy Masala, Balaji Crunchex Chilli,
    Saffola Masala Oats, Ferrero Rocher.
- Photos are matched by name, not by the catalogue's random barcodes, and the photos themselves have
  not been inspected by eye. Some show a pack from another country (for example a French Doritos pack).


### Pipeline

```
data/quarantine/generate_initial_data.py  (seed 42)
  └─ data/raw/packaged_foods_india.csv     generated records (raw)
  └─ data/products_cleaned.csv             raw + data_confidence_status (served by the app)
  └─ data/nutrition_review.csv             injected calorie anomalies (report)
  └─ data/serving_size_review.csv          injected serving-size anomalies (report)
  └─ data/data_quality_report.csv          summary counts (report)
  └─ data/dataset_manifest.json            version, provenance, row count
data/product_images.csv                    hand-curated image links (not generated)
```

Run `python data/quarantine/generate_initial_data.py` to regenerate the quarantined files. There is no separate "standardized" stage: values are already per
100 g/ml, and per-serving conversion happens at assessment time in `nutrition_validator.py`.

The dataset version (`dataset_manifest.json → dataset_version`) is shown on the
"About the data" page.

### Data dictionary (`products_cleaned.csv`)

| Column | Type | Meaning |
|---|---|---|
| product_id | text | `IND_PKG_###`, unique |
| product_name, brand | text | real names; "(Variant N)" marks generated duplicates |
| category, sub_category | text | one of 8 categories |
| serving_size, serving_size_unit | number, g/ml | stated serving |
| measurement_basis | text | `per 100g`, `per 100ml` or `unspecified` |
| energy_kcal | number | kcal per basis |
| carbohydrates_g, sugars_g, added_sugars_g, protein_g, total_fat_g, saturated_fat_g, trans_fat_g, dietary_fibre_g | number | grams per basis; blank = not stated |
| cholesterol_mg, sodium_mg | number | mg per basis |
| ingredients | text | generated ingredient list |
| additives | text | INS codes found in the ingredient text |
| allergens_declared | text | generated declaration; blank = unknown |
| marketing_claims | text | generated claims, checked by the claims auditor |
| barcode | text | 13 digits, random |
| data_source | text | provenance label |
| data_confidence_status | text | `Synthetic (not from a real label)` or a synthetic anomaly label |

Open Food Facts records (barcode lookups) use the same fields, with `data_source = Open Food Facts`
and attribution under ODbL 1.0.
